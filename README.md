# AIPA-CRS: Adaptive Intent-Preference Arbitration for Conversational Recommendation

Reproducible research prototype studying whether **explicit arbitration between a user's
long-term preference (LTP) and short-term conversational intent (STI)** improves
conversational recommendation - specifically when the two conflict.

Everything (data acquisition, leak-free preprocessing, models, baselines, ablations,
statistics, figures, tables, case studies, error analysis and the written report) is
generated by code from the English **ReDial** corpus; no number in the report is typed by hand.

## Quick start

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # or a CUDA build
pip install -r requirements.txt

# option A: notebook (RUN_MODE is set in the first cell; default "quick")
jupyter nbconvert --to notebook --execute --inplace AIPA_CRS_Research_Implementation.ipynb --ExecutePreprocessor.timeout=-1

# option B: command line, identical pipeline
python -m aipa.pipeline --run-mode quick     # ~15 min on 8 CPU cores, no GPU needed
python -m aipa.pipeline --run-mode full      # all data, more epochs/seeds/bootstraps (hours on CPU)

pytest -q                                    # unit tests
ruff check .                                 # lint
```

The first run downloads ReDial (~33 MB zip from `github.com/ReDialData/website`) and the
MovieLens `ml-latest` genre file (~350 MB zip, only `movies.csv` is kept) into `data/`.
If your machine has no internet access, place `redial_dataset.zip` in `data/raw/redial/`
and `movies.csv` in `data/external/ml-latest/` - the loader validates sizes and SHA-1 hashes
and reports source/version in the report. Without MovieLens the pipeline still runs; genre
coverage then drops and is reported as such.

## Research design in one page

* **Relationship taxonomy** (LTP vs. STI): Complement, Consistent, Conflict, Override, Uncertain.
* **Arbitration actions**: Fuse, Prioritize_LTP, Prioritize_STI, Ask_Clarification.
* **LTP** = movies the same seeker liked/saw in *earlier* ReDial dialogues (genuine ReDial
  seeker annotations) + profile sentences + genre prior. **STI** = seeker utterances *before*
  the target turn. Targets are movies the recommender introduces at that turn. No later
  information is used (temporal leakage guard; `conversationId` order is assumed chronological).
* **Label sources are always explicit**: `weak_rule` (heuristic, noisy), `synthetic_controlled`
  (injected conflicts with metadata; never mixed silently with natural data),
  `human_verified` (optional `data/annotations/human_verified.csv` with columns
  `sample_id,relationship[,action]`; reported NOT RUN when absent). ReDial has no native
  relationship labels.
* **Models**: LTP-only, STI-only, naive fusion, adaptive weighted fusion, sequential GRU
  baseline, conversation-aware baseline, AIPA ablations (w/o relationship classifier,
  w/o counterfactual diagnostic, w/o clarification, w/o temporal persistence, rule policy)
  and AIPA (full). Baselines are *approximate re-implementations*, not reproductions of
  MRGE, DiffLSRec or any published system.
* **Evaluation**: Recall/Hit/NDCG/MRR@10,20; relationship accuracy / macro-P/R/F1 / weighted
  F1 / confusion / per-class F1; arbitration accuracy, conflict-resolution accuracy, override
  success, clarification precision & efficiency, wrong-override and unnecessary-clarification
  rates; calibration (ECE, Brier); conflict vs. non-conflict subsets; sensitivity to history
  length, STI length and conflict intensity; alpha sweep; efficiency (parameters, size,
  train/inference time, GPU memory if any).
* **Statistics**: multiple seeds, 95 % bootstrap CIs, paired t and Wilcoxon tests with Holm
  correction, Cohen's d, Cliff's delta. Hypothesis verdicts (SUPPORTED / NOT SUPPORTED /
  CONTRADICTED / NOT RUN) are computed mechanically from the tests.
* **Counterfactual driver diagnostic**: LTP or STI encodings are zeroed at inference and the
  ranking disruption is measured (STI-/LTP-/Jointly-/Neither-driven). This is a
  *model-based interventional diagnostic*, not a causal-effect estimate.
* **Temporary vs. persistent shift**: a genre that wins arbitration in >= k distinct sessions
  of a seeker is folded into LTP; otherwise the override stays session-local.

## Reproducibility

* Seeds: `configs/default.yaml -> seeds`; every model/seed is trained deterministically on CPU
  (seeded `random`, `numpy` and `torch`; CPU results are bit-reproducible, GPU kernels may introduce tiny nondeterminism).
* Environment (Python, torch, CPU/GPU, package versions) and dataset hashes are written to
  `outputs/results/run_metadata.json` and Section 15 of the report.
* `outputs/` is fully regenerated on every run (`CLEAN_OUTPUTS = True`); stale artefacts cannot leak into the report.
* Full mode: `python -m aipa.pipeline --run-mode full` (or set `RUN_MODE = "full"` in the notebook).
  A GPU is optional (`device: auto`).

## Scientific-integrity rules honoured by the code

No fabricated results or labels; synthetic conflicts are always flagged; ablations and
counterfactual diagnostics are never called causal effects; unavailable analyses are `NOT RUN`;
negative and inconclusive results are reported; quick-mode results are marked provisional.
